Architecture

拒绝冗余中间件，优先选择无额外运行时、依赖少、性能强、生态成熟的技术。

01

技术选型

层级技术选型选型说明
后端语言Go 1.22+编译型语言，标准库功能完备，协程高并发，内存占用极低
后端框架Go 标准库 net/http零第三方依赖，路由与中间件足够，符合「拒绝冗余」原则
数据库SQLite 3（modernc.org/sqlite）嵌入式文件数据库，纯 Go 实现，零 CGO，交叉编译无忧
前端原生 HTML + CSS + JS（ES5）简单打包合并压缩，零运行时框架，打包后 ≤ 25KB
前端构建esbuild毫秒级构建，仅做打包与压缩
反向代理Nginx静态资源托管、SSL 终止、第一层限流、API 转发
进程托管systemd开机自启、崩溃自动重启，无需 PM2
明确拒绝引入的组件 Redis（自研 LRU 内存缓存）、消息队列（协程 + channel）、Vite / Webpack（原生三件套）、MySQL / MongoDB（SQLite 单文件）、Node.js 运行时（Go 单二进制）、用户登录注册体系（评论者零门槛）。
02

系统分层架构

前端展示层 Browser
原生 JS 评论组件（嵌入宿主页面）：渲染评论 / 提交交互 / 表情选择 / 头像展示
▼ HTTPS
反向代理层 Nginx
静态资源托管 / SSL 终止 / 第一层限流 / API 转发（127.0.0.1:8080）
▼
业务服务层 Go Backend
评论增删改查 / 鉴权 / 审核 / 限流 / 反垃圾 / 异步通知 / 数据迁移
▼ 本地文件
数据存储层 SQLite
评论 / 管理员 / 系统配置 / 限流记录 / 点赞记录 / 迁移版本（无网络交互）
职责边界 各层职责单一，仅通过约定接口 / 协议交互；前端不感知后端实现，后端不感知前端渲染；数据库仅由业务服务层访问。
03

请求流转流程

读路径：评论列表查询

用户访问页面
  → 加载 /comment/* 静态资源（Nginx 强缓存 7d）
  → 前端 GET /api/v1/comments?pageId=xxx&site=default
    → Nginx 限流检查 → 转发 Go 后端
      → 查内存缓存（key: site:page_id:page:pageSize）
        → 命中 → 直接返回
        → 未命中 → 查 SQLite（is_audited=1 + 复合索引）
          → 写缓存 → 返回

写路径：评论提交

用户提交评论
  → 前端 POST /api/v1/comment
    → Nginx 全局限流（limit_req）
    → Go 参数校验（昵称/内容/邮箱/URL 格式）
    → 敏感词检查（命中 → is_audited=-1）
      + 频率检查 + 重复内容检查
    → 写 SQLite（is_audited=0 待审，事务）
    → 返回「已提交，审核通过后显示」
    → 异步协程：通知管理员 / 缓存失效

审核路径：管理员审核

管理员审核通过
  → PUT /api/v1/admin/comment/:id/audit
    → JWT 鉴权中间件校验
    → UPDATE comments SET is_audited=1
    → 清除对应文章所有缓存分页
    → 公众可见

管理员登录

POST /api/v1/admin/register（首个用户，仅一次）
POST /api/v1/admin/login（失败不锁定，仅限流）
  → 校验 bcrypt → 签发 JWT（24h）
携带 Authorization: Bearer <token> 调用管理接口
  → JWT 鉴权 + 登出黑名单校验
POST /api/v1/admin/logout → token 入内存黑名单
04

后端核心模块

模块实现要点
路由模块http.ServeMuxAPI 版本前缀 /api/v1/；公共中间件链：Recovery → Logger → CORS → 全局限流
缓存模块（LRU）map + list + RWMutex默认 512 条、TTL 60s；key 为 site:page_id:page:pageSize；审核 / 删除时主动失效对应文章全部缓存分页
限流模块（双层）Nginx + Go 滑动窗口全局 10r/s + burst；Go 层单 IP ≤ 5 req/s；评论提交单 IP ≤ 20 条/日；登录 ≤ 5 次/分钟
反垃圾审核全量审核 + 敏感词所有评论默认待审；内嵌百级基础敏感词库，命中自动标记垃圾但仍进待审列表供人工复核
异步任务协程 + channel带缓冲队列（容量 100）：邮件通知、缓存清理、点赞记录清理（24h）、限流记录清理（30 天）
邮件通知标准库 net/smtp新评论待审通知管理员、回复通知被回复者；未配置 SMTP 时静默跳过；失败自动重试 2 次
多站点请求参数 site默认 default；缓存 key 含 site 避免污染；管理员可按站点筛选管理
05

安全设计

维度措施
输入安全全部 SQL 参数化查询（prepared statement），杜绝注入；内容二次校验（长度、格式、特殊字符过滤）；前端渲染全部转义（textContent），图片先转义再正则替换；禁止 <script> / <iframe> 等标签
接口安全管理接口 JWT 鉴权（Authorization Header，不用 Cookie，免疫 CSRF）；登出 token 入内存黑名单，重启后依赖 24h 自然过期；登录失败不做账号锁定，仅依赖接口限流；错误信息不泄露堆栈与数据库路径
内容安全本地敏感词库，命中自动标记垃圾（is_audited=-1）；全量人工审核为最后防线（不可回退）；垃圾评论前台不展示，管理员可在后台查看
账号安全密码 bcrypt 哈希（cost ≥ 12），长度 ≥ 8 位含数字字母；首个注册用户自动成为管理员，之后关闭注册；两步验证（TOTP）+ QQ / GitHub / 邮箱验证码多通道登录；IP 伪造防护：服务端从右向左取第一个非可信 IP
06

关键技术决策记录（ADR）

编号决策理由备选方案（已否决）
ADR-01SQLite 用 modernc.org/sqlite（纯 Go）零 CGO 交叉编译mattn/go-sqlite3（需 CGO）
ADR-02内存缓存用 map + RWMutex 自研 LRU无额外依赖Redis
ADR-03前端原生 JS + esbuild 打包零运行时依赖，构建仅做合并压缩Vue / React
ADR-04异步任务用协程 + channel队列容量 100 已覆盖消息队列
ADR-05后端两层返回：根评论分页 + 子评论全量减少后端复杂度，前端拼树后端树形递归
ADR-06多站点用请求参数 site防 X-Site-Id 伪造Nginx 头透传
ADR-07全量人工审核产品决策，安全优先自动通过 + 可选审核
