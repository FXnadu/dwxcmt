Background

为什么需要一套自建的、无冗余依赖、低内存占用、高性能、易部署的评论系统？

01

背景与痛点

个人博客、静态文档站（Hexo / Hugo / VitePress 等）普遍依赖 Twikoo、Waline 等第三方评论服务，这些方案存在以下四大痛点：

依赖外部服务

第三方服务一旦关停、改版，评论功能即不可用，站点的读者互动能力完全受制于人。

资源开销大

Node.js 运行时内存占用高，对于 1 核 1G 的小型服务器是沉重负担。

数据不自主

评论数据存放在他人平台，迁移成本高，无法真正拥有自己的社区内容。

部署复杂

依赖 Node.js 环境、云函数等，运维繁琐，升级与备份都需要额外学习成本。

结论 需要一套 无冗余依赖、低内存占用、高性能、易部署 的自建评论系统。
02

产品定位

极致轻量的自托管评论系统：单二进制 + 单文件数据库 + 纯静态前端

  • ↳
    替代对象 Twikoo、Waline 等轻量评论服务
  • ↳
    目标用户 技术博客作者、静态站点站长、自托管爱好者
  • ↳
    核心理念 极致轻量、零重型依赖、数据完全自主、运维成本极低
03

设计目标（质量属性）

目标量化指标优先级
极致轻量后端单二进制 + 单数据库文件，前端打包 ≤ 25KBP0
低资源占用整机服务总内存 ≤ 100MB，适配 1 核 1G 服务器P0
高性能接口响应毫秒级，支持千级日活P0
高稳定无第三方平台依赖，常驻无冷启动，长期免人工干预P0

04

适用场景与范围

适用场景

  • ✓
    个人博客（Hexo / Hugo / VitePress 等静态站）
  • ✓
    文档站点、个人作品站
  • ✓
    日访问量 ≤ 5000、日均评论 ≤ 200 的中小站点
  • ✓
    需要完全自托管、避免第三方服务关停风险的场景

明确不做（非目标）

  • ✕
    评论者注册 / 登录体系（零门槛）
  • ✕
    用户编辑 / 删除自己的评论（发后不改）
  • ✕
    富文本 / 完整 Markdown 编辑器（仅纯文本 + 图片 URL + Emoji）
  • ✕
    实时推送 / WebSocket（采用轮询式刷新）
  • ✕
    评论软删除、取消赞、举报功能
05

用户角色定义

访客

浏览博客并发表评论的普通用户。核心诉求：快速发表、表情 / 图片支持、回复通知、无需注册。

被回复者

收到回复通知的评论者。核心诉求：通过邮件收到回复提醒。

站长 / 管理员

博客所有者。核心诉求：全量审核、删除垃圾、置顶、数据备份迁移、第三方绑定。
