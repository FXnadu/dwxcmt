Implementation

文档驱动的开发方法：先写清楚「做什么」与「怎么做」，再逐层实现、测试、压测、上线。

01

开发方法：文档驱动

项目采用「先文档、后代码」的流程，任何功能先经历需求评审与设计评审，形成 7 份规格文档，再进入开发。文档即契约：

文档回答的问题
01-需求规格说明书「做什么」：背景、定位、功能清单、20 条产品决策、验收要点
02-系统架构设计「怎么设计」：选型、分层、流程、模块、安全、ADR
03-数据库设计文档表结构、索引、SQLite 优化、迁移策略、数据访问模式
04-API 接口文档统一响应、错误码、全部公开 / 管理接口契约
05-前端实现方案组件架构、渲染规则、XSS 防护、嵌入方式、性能约束
06-部署运维手册编译、systemd、Nginx、备份恢复、升级、故障排查
07-性能测试报告压测方法、实测数据、内存表现、线上验证

03

实际制作流程

  1. 需求分析与澄清 梳理第三方评论服务痛点，产出《需求规格说明书》；通过两轮评审修正 19 处矛盾，固化 20 条产品决策与「不做清单」。
  2. 架构与数据库设计 确定技术选型（Go + SQLite + 原生 JS），定义四层架构、请求流转、模块边界；设计 6 张表、复合索引与 SQLite WAL 优化。
  3. 搭建工程骨架 初始化 go.mod、main.go 入口（配置加载、安全自检、优雅退出）、config 解析、model 数据库打开与自动迁移框架。
  4. 实现路由与中间件链 router 注册全部 /api/v1/ 路由；中间件链 Recovery → Logger → CORS → 全局限流；管理组挂 JWT 鉴权 + 登出黑名单。
  5. 实现业务服务层 按模块迭代：评论 / 审核 / 鉴权 / 反垃圾 / 置顶 / 站点配置 / 站长回复 / 数据迁移 / 个人中心 / 账号管理，每个模块配套单元测试。
  6. 开发前端评论组件 原生 ES5 实现渲染、拼树、表情面板、头像、暗黑模式、分页与表单交互；XSS 全部转义；与后台视觉语言统一。
  7. 构建与打包 esbuild 打包压缩前端（≤ 25KB）；Go 交叉编译零 CGO 单二进制，通过 -ldflags 注入版本号。
  8. 测试与压测 单元测试覆盖核心逻辑；hey 压测读路径 / 写路径，pprof 观测内存与 goroutine；修复压测脚本缺陷。
  9. 部署上线与验证 systemd 托管 + Nginx 反代，上线 cmt.example.com 实测：TTFB、限流精确性、CORS、TLS、IP 伪造防护。

项目目录结构

dwxcmt/
├── main.go                 # 入口：配置、安全自检、优雅退出、pprof 观测
├── config/                 # 配置加载与解析（含压测专用配置）
├── router/                 # 路由注册与中间件链组装
├── controller/             # HTTP 层：公开 / 管理 / 设置 / 置顶 / 迁移 / 个人中心
├── service/                # 业务逻辑：评论 / 审核 / 鉴权 / 反垃圾 / 权限 / 两步验证
├── model/                  # 数据模型与 SQLite 初始化
├── middleware/             # auth / cors / logger / ratelimit / recovery
├── pkg/                    # cache(LRU) / email(SMTP) / sensitive(词库) / utils
├── migration/              # 9 个版本化迁移脚本（embed 打包）
├── front/                  # 评论组件 + 管理后台（原生 HTML/CSS/JS）
├── scripts/                # 压测（stress）/ 监控（monitor）/ 演示数据（seed）
└── docs/                   # 7 份规格文档
依赖方向 main → router → controller → service → model，pkg/* 被各层引用，禁止反向依赖。
06

构建与发布

前端打包（esbuild）

"build": "esbuild front/comment.js --minify --outfile=front/comment.min.js && esbuild front/comment.css --minify --outfile=front/comment.min.css"

后端交叉编译（零 CGO）

# Linux amd64 / arm64，版本号注入健康检查
GOOS=linux GOARCH=amd64 go build -ldflags="-s -w -X dwxcmt/controller.Version=v1.0.0" -o dwx-comment main.go
环节方式
部署复制二进制 + config.yaml + front/ + migration/ 到 /opt/dwx-comment
托管systemd 服务：Restart=always、优雅退出 30s、开机自启
反向代理Nginx：静态资源强缓存 7d、/api/ 转发 + 限流 10r/s burst 10
升级备份 → 替换二进制 + 迁移脚本 → 重启（自动执行数据库迁移）→ 健康检查验证
备份WAL checkpoint 后拷贝 comment.db，或管理接口全量导出 / 一键备份
07

测试与质量保障

单元测试

覆盖评论、回复、审核、反垃圾、两步验证、邮件通知（mock SMTP）、限流、工具函数等核心路径，随模块迭代同步编写。

性能压测

hey 并发压测读 / 写路径，pprof 观测内存与 goroutine；压测配置独立隔离（stress.db），不污染生产数据。

线上验证

真实部署后验证限流精确性、CORS 白名单、TLS、IP 伪造防护、静态缓存等安全与运维项。

安全测试

CORS 未白名单拦截、X-Forwarded-For 伪造无效、错误信息不泄露内部细节。
