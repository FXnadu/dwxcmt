## 1. 项目概述

### 1.1 背景与痛点

个人博客、静态文档站（Hexo/Hugo/VitePress 等）普遍依赖 Twikoo、Waline 等第三方评论服务，存在以下痛点：

| 痛点 | 说明 |
|------|------|
| 依赖外部服务 | 第三方服务关停、改版即导致评论功能不可用 |
| 资源开销大 | Node.js 运行时内存占用高，小型服务器压力大 |
| 数据不自主 | 评论数据存放在他人平台，迁移成本高 |
| 部署复杂 | 依赖 Node.js 环境、云函数等，运维繁琐 |

**结论**：需要一套无冗余依赖、低内存占用、高性能、易部署的自建评论系统。

### 1.2 产品定位

**一句话**：极致轻量的自托管评论系统，单二进制 + 单文件数据库 + 纯静态前端。

- **替代对象**：Twikoo、Waline 等轻量评论服务
- **目标用户**：技术博客作者、静态站点站长、自托管爱好者
- **核心理念**：极致轻量、零重型依赖、数据完全自主、运维成本极低

### 1.3 核心理念（v2 新增，源自产品决策）

| 理念 | 说明 | 决策来源 |
|------|------|----------|
| 零用户门槛 | 评论者无需注册、无需登录，填昵称即可发言 | 决策 #2 |
| 全量审核 | 所有评论默认待审核，管理员通过后才对公众可见 | 决策 #1 |
| 发后不改 | 评论提交后用户不可编辑、不可删除，误发联系管理员处理 | 决策 #3 |
| 极致轻量 | 宁可功能收敛，不做过度设计 | — |

> ⚠️ v1 的「默认自动通过 + 可选审核」模式已废弃，统一改为全量审核。此决策不可回退。

| 目标 | 量化指标 | 优先级 |
|------|----------|--------|
| 极致轻量 | 后端单二进制 + 单数据库文件，前端打包 ≤ 25KB | P0 |

| 高性能 | 接口响应毫秒级，支持千级日活 | P0 |

| 体验友好 | 表情、回复提醒、数据迁移、图片等实用功能 | P1 |

## 3. 适用场景与范围

### 3.1 适用场景
- 个人博客（Hexo / Hugo / VitePress 等静态站）
- 文档站点、个人作品站
- 日访问量 ≤ 5000、日均评论量 ≤ 200 的中小站点
- 需要完全自托管、避免第三方服务关停风险的场景

### 3.2 明确不做（非目标 / v2 已裁剪）

| 不做项 | 决策理由 |
|--------|----------|
| 评论者注册/登录体系 | 零门槛，评论者与管理员走完全不同通道（决策 #2） |
| 用户编辑/删除自己评论 | 发后不改（决策 #3） |
| 评论软删除 | 误删重发即可，仅物理删除（决策 #4） |
| 取消赞 / 踩 | 只做正面点赞，保持交互简洁（决策 #8） |
| 举报功能 | 不需要（决策 #7） |
| 富文本/Markdown 编辑器 | 仅纯文本 + Markdown 图片语法 `![](url)` + Emoji |
| 实时推送/WebSocket | 采用轮询式刷新 |
| 多语言国际化框架 | `data-locale` 预留，一期仅中文 |

## 4. 用户角色定义

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 访客 | 浏览博客并发表评论的普通用户 | 快速发表、表情/图片支持、回复通知、**无需注册** |
| 被回复者 | 收到回复通知的评论者 | 通过邮件收到回复提醒 |
| 站长/管理员 | 博客所有者 | **全量审核**、删除垃圾、置顶、数据备份迁移、第三方绑定 |

## 5. 功能需求清单

### 5.1 评论核心功能（P0）

| 编号 | 需求 | 说明 | 验收要点 |
|------|------|------|----------|
| FR-01 | 发表评论 | 昵称（必填）、内容（必填）、邮箱/网站（选填）；内容支持 Markdown 图片语法 `![](url)` | 校验通过后 `is_audited=0` 入库，提示待审 |
| FR-02 | 回复评论 | 对任意层级评论回复，`@昵称` 提示 | 回复正确挂载到父评论下 |
| FR-03 | 评论列表分页 | 「加载更多」/页码分页器（配置切换）；**后端返回两层结构**：根评论分页 + 子评论全量；根评论排序：置顶优先（按**置顶时间倒序**，后置顶的排最上）→ 时间倒序（最新在前，默认）；支持 `sort` 切换最旧在前 / 按热度；排序末尾 `id` 兜底防并列乱序；子评论时间正序 | 仅含 `is_audited=1`，数据完整无重复；默认 10 条/页，公开接口最大 50、管理接口最大 100，**页码从 1 开始** |
| FR-04 | 评论计数 | 展示某页面评论总数（仅已审核） | 数字与列表一致 |
| FR-05 | 批量评论计数 | 已取消：无前端使用，接口已移除（原为首页多文章评论数一次取回，最多 100 个 `pageId`） | — |
| FR-06 | 最近评论 | 已取消：无前端使用，接口已移除（原为最新评论侧边栏，默认 10 条，按 `site` 隔离，仅已审核） | — |

### 5.2 交互增强功能（P1）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-07 | Emoji 表情面板 | 内置面板点击插入，`:)` 快捷转义 |
| FR-08 | 用户信息记忆 | 昵称/邮箱/网站存 localStorage 自动填充 |
| FR-09 | 回复邮件通知 | **默认勾选**「有回复时通知我」；未填邮箱则忽略通知；邮件正文中的评论链接携带**评论锚点**（`#comment-{id}`），点击直达对应评论 |

| FR-13 | 暗黑模式 | CSS 变量 + `prefers-color-scheme` 自动适配 |

### 5.3 点赞功能（P1）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-14 | 评论点赞 | 基于 IP + `likes` 表 24h 去重，原子递增；**不提供取消赞**；24h 内同一 IP 对同一评论只能点赞一次 |

### 5.4 管理功能（P1）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-15 | 管理员登录 | 用户名+密码，JWT 有效期 24h；**首个注册的用户自动成为站长（可直接登录）**；后续注册进入**站长审批**（未通过不可登录），站长可审批/禁用账号、授予或收回删除权限；支持**邮箱验证码登录**与**两步验证（2FA）**；不做失败锁定 |
| FR-16 | 管理员登出 | token 加入内存黑名单（24h 自动清理） |
| FR-17 | QQ 互联登录 | OAuth 授权登录，首次需绑定本地管理员账号 |
| FR-18 | 评论删除 | 物理删除（含子回复级联），不做软删除 |
| FR-19 | 评论审核 | 通过/标记垃圾，通过时清缓存；待审列表仅提供「通过」按钮，标记垃圾走单独操作 |
| FR-20 | 待审核列表 | 显示 `is_audited=0`（待审）和 `is_audited=-1`（垃圾）按时间倒序 |
| FR-21 | 全量评论列表 | 按状态+站点筛选 + 关键词搜索（搜昵称/内容/邮箱）+ **排序**（`newest` 最新在前默认 / `oldest` / `hot`）；已通过/垃圾 tab 均支持关键词搜索 |
| FR-22 | 评论置顶/取消置顶 | 仅已审核根评论可置顶；每文章最多 3 条（可配置）；**置顶区按置顶时间倒序**（后置顶的排最上），取消置顶清空置顶时间 |
| FR-23 | 站点配置 | `settings` 表采用 key-value 结构，用户自定义；覆盖站点名、站点地址（`siteUrl`）、SMTP、置顶上限、每页条数、翻页方式（`pagerType`）、站长昵称/徽章/头像等 |
| FR-24 | 站长回复评论 | 管理员在后台以站长身份回复任意评论；回复标记 `is_admin=1`，前台展示「站长」徽章，**直接已审核即时可见**；自动挂载到目标评论下（`parent_id`/`root_id` 推导）、清理文章缓存，并触发被回复者邮件通知；站长昵称、徽章文案与站长头像可在后台设置中自定义（`adminNick`/`adminBadge`/`adminAvatar`），前台站长评论优先展示站长头像 |

## 6. 非功能需求

### 6.1 性能（P0）
| 指标 | 目标 |
|------|------|
| 缓存命中查询 | < 5ms |
| 数据库查询（≤1000 条评论） | < 15ms |
| 评论提交（含敏感词检测+写入，不含异步任务） | < 50ms |
| 并发 QPS | ≥ 500（1核2G 压测） |
| 5000 PV/日 | 资源几乎无波动 |

### 6.2 资源占用（P0）
| 组件 | 预估占用 |
|------|----------|
| Go 后端 | 25~45MB |
| SQLite 内存映射 | 5~10MB |
| Nginx | 5~10MB |
| **整机合计** | **≤ 100MB**（最低支持 1核512MB） |

### 6.3 安全（P0）
- 全部 SQL 参数化查询，杜绝注入
- 输出转义，防 XSS；图片魔数校验，拒绝 SVG
- 管理接口 JWT 鉴权（Header 传递，不用 Cookie，免疫 CSRF）；登录仅做接口限流，不做账号锁定
- 错误信息不泄露堆栈与路径

### 6.4 兼容性（P1）
- 前端 ES5 语法，兼容 Chrome / Firefox / Safari / Edge 现代版本
- 服务端 Linux x86_64 / arm64（纯 Go 交叉编译，零 CGO）

### 6.5 可运维性（P0）
- 单二进制部署，systemd 托管自动重启
- 版本升级自动执行数据库迁移
- 优雅退出最长等待 30 秒（决策 #20）

## 10. 需求澄清与落地约定（v2.1 新增）

> 本节记录 2026-08-05 讨论后明确的需求细节，开发以本节为准。

### 10.1 配置管理
- `settings` 表采用 **key-value 结构**，所有用户可配置项均不硬编码。
- 覆盖范围：站点名、SMTP 服务器、通知开关、每页条数、置顶上限、链接限制等。

### 10.2 管理员账号
- **首个注册的用户自动成为站长**（`is_owner=1`，可直接登录）；注册入口不再关闭。
- 后续注册账号进入**待审批**状态，站长在后台审批通过后方可登录；站长可禁用账号、授予/收回删除权限。
- 支持**邮箱验证码登录**（绑定邮箱后）与**两步验证 2FA**（密码 + 邮箱验证码）。
- 提供登录后修改密码接口；忘记密码需通过数据库或重新部署处理。
- 不做登录失败锁定，仅依赖通用接口限流。
- 登出 token 黑名单仅存内存，重启后丢失可接受（JWT 24h 自然过期）。

### 10.3 评论格式与渲染
- 支持 **Markdown 图片语法** `![](url)`；其余 Markdown 语法（标题/列表/加粗等）不支持。
- 评论内容为纯文本 + 换行 + Emoji 面板 + Markdown 图片语法。

### 10.4 头像
- 前端**不暴露邮箱字段**；后端统一返回**有序候选数组 `avatarUrls`**。
- 有邮箱：按「QQ 邮箱代理（本服务 `/api/v1/avatars/{id}`，防暴露 QQ 号）→ Cravatar → Gravatar」顺序返回候选地址。
- 无邮箱：后端不返回 `avatarUrls`，前端基于昵称哈希生成几何图形 SVG（随机颜色 + 图形）。
- 前端按序加载，任一候选**超时（如 3 秒）自动跳过**到下一候选；全部失败回退字母头像。

### 10.5 评论列表与分页
- 后端返回**两层结构**：根评论分页 + 子评论全量返回。
- 根评论排序：置顶区固定按**置顶时间倒序**（后置顶的排最上）→ 普通区按 `sort`（`asc` 最新在前默认 / `desc` 最旧在前 / `hot` 按点赞数）；排序末尾追加 `id` 兜底。
- 子评论按时间正序。
- 翻页方式由站点配置 `pagerType` 控制：`more`（加载更多按钮，默认）/ `pages`（页码分页器）。
- 移动端回复采用**扁平化展示**（直接展示回复内容，不做深层嵌套折叠）。
- 默认每页 10 条，公开接口最大 50 条、管理接口最大 100 条，**页码从 1 开始**。
- 回复层级**不限深度**；前端默认展开 3 层，更深层级折叠显示。

### 10.6 审核与反垃圾
- 敏感词命中后直接标记 `is_audited=-1`（垃圾），但仍显示在待审列表中。
- 待审列表操作按钮仅提供「通过」；标记为垃圾走单独操作。
- 频率限制仅针对**评论提交接口**：单 IP 每秒 ≤5 次、每日 ≤20 条。
- 重复内容拦截：5 分钟内、同一 `pageId`、同一 IP 连续相同内容拦截。
- 链接限制默认不限制。

### 10.7 邮件通知
- SMTP 配置、通知开关、站点名均存于 `settings` 表；新增**站点地址 `siteUrl`** 用于拼接评论链接。
- 回复通知默认勾选；未填邮箱时忽略通知；通知邮件中的评论链接携带**锚点 `#comment-{id}`**，点击直达对应评论。
- 新评论管理员通知默认开启；未配置 SMTP 时静默跳过。

### 10.8 多站点与站点标识
- 通过请求参数 `site` 传递；未传时默认 `site=default`。
- 管理员可按站点筛选，可管理全部站点。

### 10.9 数据迁移与备份
- 导入数据保留原平台字段（如 `source`、`created_at`、`user` 等），**默认标记为已审核**。
- 导出为全量导出（包含 comments、admins、settings、likes、rate_limits、migration_versions 等）。
- 备份：提供管理接口 `GET /api/v1/admin/backup`，服务端执行 WAL checkpoint 后直接下载 `comment.db` 文件快照；亦支持文件级手动备份（详见《06-部署运维手册》§5）。
