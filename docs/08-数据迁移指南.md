# dwxComment 数据迁移指南 v3.1

> 版本：v3.1 ｜ 适用场景：从 Waline / Twikoo / Disqus 迁移至 dwxComment
> 关联需求：FR-33 数据导出、FR-34 数据导入、FR-36 一键备份
> 关联接口：见《04-API接口文档.md》第 4 章「数据迁移接口（管理员）」

---

## 1. 迁移概述

dwxComment 内置数据导入导出能力，管理员可在**后台「数据管理」页**完成迁移，无需改库脚本。

| 项 | 说明 |
|----|------|
| 支持来源 | Waline、Twikoo、Disqus、dwxComment 自身导出文件 |
| 迁移内容 | 评论正文、昵称、邮箱、链接、页面标识、父评论层级、时间、审核状态、置顶、IP、UA |
| 不迁移内容 | 点赞记录（点赞需用户重新操作）、头像（按邮箱经 Gravatar 重新生成）、站点配置 |
| 迁移方式 | 后台界面 或 HTTP 接口（`POST /api/v1/admin/migrate`） |
| 文件限制 | 单次导入文件 ≤ 5MB（JSON） |
| 迁移前建议 | 先「一键备份」留空库快照，出错可回滚 |

---

## 2. 迁移前置准备

### 2.1 导出 Waline 数据

1. 登录 Waline 后台，进入 **管理 → 导入导出 → 导出**，获取 JSON 导出文件；也可从 Waline 的存储控制台（LeanCloud / MongoDB）导出 comment 表，整理为 JSON 数组。

Waline 导出格式（JSON 数组，每条记录字段示意）：

```json
[
  {
    "comment": { "nick": "访客", "mail": "a@b.com", "link": "", "content": "正文", "ua": "Mozilla/...", "url": "https://blog.com/post/hello.html" },
    "insertedAt": 1620000000000,
    "objectId": "5f...",
    "pid": "",
    "status": "approved",
    "ip": "1.2.3.4",
    "isSticky": false
  }
]
```

> 解析器兼容 `comment` 为 **JSON 字符串**或**对象**两种形态，也兼容字段平铺在记录顶层（nick/mail/link/content/ua/url）的写法；时间支持秒级/毫秒级时间戳与常见日期字符串。

### 2.2 文件超限处理

单次导入上限 5MB（`service.MaxImportBytes`）。若导出文件超过 5MB：

- 用脚本按记录数拆分为多个 JSON 数组文件，分批导入；
- 导入按 `page_id + content` 去重，重复记录会自动跳过，分批导入安全。

### 2.3 其他来源（可选）

- **Twikoo**：选择器选 `twikoo`，解析 `comment` 对象与 `created/updated` 时间。
- **Disqus**：选择器选 `disqus`，解析 `message/author/thread`，页面标识取 thread 的 `identifier/link`。
- **dwxComment 自身导出**：文件含 `pageId` 字段时自动识别，无需手动选择格式。

## 4. 导入评论数据

### 4.1 后台界面导入（推荐）

1. 后台 → **数据管理 → 导入评论**；
2. **数据源格式**选择 `waline`；
3. 选择 JSON 文件（≤5MB），点击**导入**；
4. 等待返回结果：`新增 N 条，跳过 M 条`。

### 4.2 HTTP 接口导入

```
POST /api/v1/admin/migrate        （需管理员 JWT）
Content-Type: multipart/form-data

字段：
  source  = waline                 # waline | twikoo | disqus | dwxcomment
  file    = comments.json          # JSON 数组文件，≤5MB
```

响应：

```json
{ "code": 0, "msg": "success", "data": { "imported": 120, "skipped": 3 } }
```

### 4.3 导入规则

| 规则 | 行为 |
|------|------|
| 审核状态映射 | Waline `approved`→已通过、`waiting/pending`→待审核、`spam`→垃圾；未解析到状态时**默认已通过（已审核）** |
| 去重 | 同 `page_id + content` 已存在则跳过（计入 skipped） |
| 父评论重建 | 按源 `pid` 在本批次内映射为新的父子关系；父评论必须同页同站，否则降级为根评论导入 |
| 数据校验 | 缺失昵称/内容/页码或超长的记录跳过（计入 skipped） |
| 时间 | 保留源时间（秒/毫秒自动归一）；缺失时取导入时刻 |
| 站点 | Waline 无站点概念，导入后归入 `default` 站点（空 site 归一化为 `default`） |
| 原子性 | 单次导入整体走事务，中途失败全部回滚 |

## 5. 页面标识（pageId）对齐（重要）

导入后，Waline 的 `url` 字段会成为评论的 `page_id`（通常是**完整链接**，如 `https://blog.com/post/hello.html`）。

而 dwxComment 前端组件**默认使用 `window.location.pathname`**（即 `/post/hello.html`）作为页面标识。两者不一致会导致**已导入的旧评论无法在页面上展示**。二选一解决：

### 方案 A：容器指定页面 ID（推荐静态站点）

在模板中显式指定与 Waline 一致的完整链接：

```html
<div data-page-id="https://blog.com/post/hello.html" data-server="https://你的域名"></div>
```

### 方案 B：预处理导出文件

导入前用脚本将导出文件中的 `url`（及 `comment.url`）统一替换为 pathname 形式：

```javascript
// Node.js 示例：将完整链接转 pathname 后重新写入（兼容 comment 为对象或 JSON 字符串两种形态）
const fs = require('fs');
const list = JSON.parse(fs.readFileSync('waline-export.json', 'utf8'));
for (const it of list) {
  if (typeof it.comment === 'string') {
    try { it.comment = JSON.parse(it.comment); } catch (e) { it.comment = {}; }
  }
  const raw = (it.comment && it.comment.url) || it.url || '';
  const path = new URL(raw, 'https://placeholder.local').pathname;
  if (it.comment && typeof it.comment === 'object') it.comment.url = path;
  it.url = path; // 同时写顶层 url，兼容两种解析路径
}
fs.writeFileSync('waline-path.json', JSON.stringify(list));
```

> 方案 A 每页需写死 ID，适合页面固定的静态站；方案 B 一次处理、全站生效，但需保证模板路径与转换结果完全一致。两种方案选一种，导入后务必抽查验证。

## 6. 替换前端 Waline 脚本

### 6.1 基础嵌入

在博客模板（Hexo/Hugo/VitePress 等）中将 Waline 引入替换为 dwxComment 组件：

```html
<!-- 容器：不指定 data-page-id 时默认取当前路径，需与导入数据 page_id 对齐（见第 5 章） -->
<div id="dwx-comment" data-server="https://你的域名"></div>

<script>
  window.dwxComment = {
    server: 'https://你的域名',   // API 地址，同源可省略
    site: 'default',              // 站点标识，须与导入时归属站点一致
    locale: 'zh-CN',
    pageSize: 10,
    sort: 'asc',
    maxDepth: 3,
    darkMode: 'auto'
  };
</script>
<script src="/comment/comment.js" defer></script>
<link rel="stylesheet" href="/comment/comment.css">
```

> 站点标识说明：Waline 无站点概念，导入数据归入 `default`；若博客配置了多站点，导入前先确认 `site` 归属。

### 6.2 组件配置项

组件为**原生 ES5、零框架依赖**的单文件组件（`front/comment.js` + `front/comment.css`），支持三种自定义层级：改配置、改样式、改源码（见 6.5）。

配置优先级（从高到低）：**容器 `data-*` 属性 > `window.dwxComment` 全局对象 > 内置默认值**。

| 配置 | 类型 / 取值 | 默认 | 说明 |
|------|-------------|------|------|
| server | 字符串 | `''`（同源） | API 地址，跨域部署时必填 |
| site | 字符串 | `default` | 站点标识，须与导入数据归属站点一致 |
| locale | 字符串 | `zh-CN` | 界面语言（预留配置，当前界面文案固定为中文） |
| pageSize | 数字 | `10` | 每页评论条数 |
| sort | `asc` / `desc` / `hot` | `asc` | 排序：最新 / 倒序 / 热度 |
| maxDepth | 数字 | `3` | 回复嵌套最大层级 |
| emojiPanel | 布尔 | `true` | 表情面板开关 |
| darkMode | `auto` / `light` / `dark` | `auto` | 明暗主题模式 |
| maxLength | 数字 | `500` | 评论字数上限（服务端 site-config 返回后覆盖） |

容器 `data-*` 写法（优先级最高，适合静态站模板）：

```html
<div id="dwx-comment"
     data-page-id="/post/hello.html"
     data-server="https://api.example.com"
     data-site="default"
     data-locale="zh-CN"
     data-page-size="10"
     data-sort="asc"
     data-max-depth="3"
     data-emoji-panel="true"
     data-dark-mode="auto"></div>
```

### 6.3 主题与样式自定义（CSS 变量）

组件全部颜色、圆角、间距均由 `.lc-wrap` 上的 CSS 变量驱动，**在你的站点 CSS 中覆盖变量即可整体换肤，无需改动组件源码**：

| 变量 | 说明 |
|------|------|
| `--lc-bg` | 组件背景 |
| `--lc-surface` / `--lc-surface-strong` | 卡片 / 输入框表面 |
| `--lc-text` / `--lc-text-2` | 正文 / 次级文本 |
| `--lc-border` / `--lc-border-hover` | 边框 / hover 边框 |
| `--lc-accent` / `--lc-accent-text` | 主色 / 主色上的文字 |
| `--lc-hover` | hover 背景 |
| `--lc-danger` | 错误 / 删除色 |
| `--lc-admin-bg` / `--lc-admin-text` / `--lc-admin-border` | 站长徽标配色 |
| `--lc-pending-bg` / `--lc-pending-border` | 待审核标记配色 |
| `--lc-radius` | 圆角（默认 2px） |
| `--lc-gap` | 组件内间距（默认 16px） |

主题模式说明：
- `darkMode: 'auto'`（默认）：跟随系统，`prefers-color-scheme: dark` 时自动切暗色变量；容器带 `data-theme="light"` 则强制亮色；
- `darkMode: 'dark'`：强制暗色（组件在 `.lc-wrap` 上设置 `data-theme="dark"`）；
- `darkMode: 'light'`：强制亮色（设置 `data-theme="light"`）。

换肤示例（写入博客自己的样式文件）：

```css
/* 在自己的站点 CSS 中覆盖组件变量即可整体换肤 */
#dwx-comment .lc-wrap {
  --lc-accent: #e67e22;       /* 主色改为橙色 */
  --lc-radius: 8px;           /* 圆角改大 */
  --lc-surface: #ffffff;      /* 表面改纯白 */
  --lc-gap: 20px;             /* 间距调大 */
}
```

### 6.4 监听自定义事件

组件在容器元素上派发 `CustomEvent`，可挂监听做统计、联动等：

| 事件 | `detail` | 触发时机 |
|------|----------|----------|
| `lc:ready` | `{}` | 组件渲染完成 |
| `lc:count` | `{ count }` | 评论总数加载完成 |
| `lc:loaded` | `{ page }` | 某页列表加载完成 |
| `lc:submitted` | `{ id }` | 评论提交成功 |
| `lc:error` | `{ msg }` | 加载 / 提交失败 |

```js
document.getElementById('dwx-comment').addEventListener('lc:submitted', function (e) {
  console.log('新评论 id:', e.detail.id);   // 可在此做埋点统计
});
```

### 6.5 深度自定义（改结构 / 完全自研）

| 自定义层级 | 做法 |
|-----------|------|
| 1. 只换肤 | 覆盖 CSS 变量（见 6.3），不动 JS |
| 2. 改交互 / 文案 / DOM 结构 | 将 `front/comment.js` 复制到自建目录后修改（组件 DOM 模板内嵌于 JS），保持对外配置项与 `lc:*` 事件约定不变，便于跟随上游接口升级 |
| 3. 完全自研前端 | 不引入组件，直接对接 REST API（评论列表 / 提交 / 点赞 / 站点配置等，见《04-API接口文档.md》），页面实现完全自由 |

> 注意：`front/comment.js`（v0.1.0）与 `front/comment.css`（v0.3.0）版本独立，源码头部注释标注了版本号；升级服务端时如组件有更新，建议同步覆盖自定义副本。

## 7. 导入后验证

1. **数据核对**：后台 → 数据管理 → 导出 JSON，核对条数与源站一致（`imported + skipped` ≈ 源评论数）。
2. **页面展示**：打开博客任意有旧评论的页面，确认评论按预期展示、层级/置顶/审核状态正确。
3. **待审核项**：源站 `waiting` 评论进入后台**待审列表**、`spam` 评论进入**垃圾箱**，按需处理。
4. **新评论回归**：发一条新评论，验证通知、审核、点赞链路正常。

## 8. 回滚与并行方案

### 8.1 迁移前备份（必做）

后台 → **数据管理 → 一键备份**，生成数据库文件级快照并下载保存；也可用接口：

```
GET /api/v1/admin/backup
```

### 8.2 并行运行与下线

1. 迁移完成后让 Waline 与 dwxcmt **并行运行数天**，观察数据一致性与新评论表现；
2. 确认稳定后，关闭 Waline 服务、停用其数据库，并删除博客模板中的 Waline 脚本；
3. 若迁移有问题，可恢复备份的 `comment.db` 回滚，博客随时切回 Waline。

## 9. 常见问题（FAQ）

| 问题 | 原因 / 处理 |
|------|-------------|
| 导入报「导入文件不能超过 5MB」 | 文件超限，按第 2.2 节拆分后分批导入 |
| 旧评论在页面上不显示 | `page_id` 未对齐，按第 5 章处理 |
| `skipped` 数量异常大 | 多为重复记录（去重跳过）或非法记录（缺昵称/内容/页码）；导出 JSON 核对即可 |
| 评论显示为待审核 | 源数据 `status=waiting/pending` 原样保留，属预期；去后台待审列表通过即可 |
| 评论层级错乱 | 父评论跨页/跨站时被降级为根评论，属预期保护逻辑，防止幽灵数据 |
| 点赞数丢失 | 点赞记录不迁移，需用户重新点赞，属预期 |
| 头像不一致 | 头像按邮箱经 Gravatar 生成，非源站头像，属预期 |
