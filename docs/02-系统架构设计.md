## 1. 技术选型

### 1.1 选型原则
优先选择无额外运行时、依赖少、性能强、生态成熟的技术，**拒绝冗余中间件**。

| 层级 | 技术选型 | 选型说明 |
|------|----------|----------|
| 后端语言 | Go 1.22+ | 编译型语言，标准库功能完备，协程高并发，内存占用极低 |
| 后端框架 | Go 标准库 `net/http` + `gin`(可选) | 零第三方依赖亦可；Gin 仅增加 1 个核心依赖，提升路由与中间件效率 |
| 数据库 | SQLite 3（`modernc.org/sqlite` 纯 Go 实现） | 嵌入式文件数据库，零 CGO，交叉编译无忧，读性能强 |
| 前端 | 原生 HTML + CSS + JavaScript | 简单打包合并压缩，零运行时框架，打包后 ≤ 25KB |
| 反向代理 | Nginx | 静态资源托管、SSL 终止、接口限流、反向代理 |
| 进程托管 | systemd | 开机自启、崩溃自动重启，无需 PM2 |

### 1.2 明确拒绝引入的组件

| 组件 | 拒绝原因 | 替代方案 |
|------|----------|----------|
| Redis | 引入额外进程与内存开销 | Go 原生 `map + sync.RWMutex` 内存缓存 |
| 消息队列 | 过度设计 | Go 协程 + channel 实现异步队列 |
| 重型前端构建工具（Vite/Webpack） | 增加构建复杂度 | 原生三件套 + 最小化合并压缩脚本 |
| 独立数据库（MySQL/MongoDB） | 内存开销大、运维复杂 | SQLite 单文件 |
| Node.js 运行时 | 不依赖任何服务端 JS 环境 | Go 单二进制 |
| 用户登录/注册体系 | 评论者零门槛，与管理员走完全不同通道 | 评论者无需认证 |

## 2. 系统分层架构

```
┌─────────────────────────────────────────────────────┐
│  前端展示层   原生 JS 评论组件（嵌入宿主页面）         │
│  渲染评论 / 提交交互 / 表情选择                        │
└─────────────────────────┬───────────────────────────┘
                          │ HTTPS
┌─────────────────────────▼───────────────────────────┐
│  反向代理层   Nginx                                  │
│  静态资源托管 / SSL 终止 / 第一层限流 / API 转发       │
└─────────────────────────┬───────────────────────────┘
                          │ 127.0.0.1:8080
┌─────────────────────────▼───────────────────────────┐
│  业务服务层   Go 后端                                │
│  评论增删改查 / 鉴权 / 审核 / 限流 / 反垃圾           │
│  / 异步通知 / 数据迁移                                │
└─────────────────────────┬───────────────────────────┘
                          │ 本地文件
┌─────────────────────────▼───────────────────────────┐
│  数据存储层   SQLite 单文件数据库                     │
│  评论 / 管理员 / 系统配置 / 限流记录 / 点赞记录        │
│  / 迁移版本（无网络交互）                             │
└─────────────────────────────────────────────────────┘
```

**职责边界**：各层职责单一，仅通过约定接口/协议交互；前端不感知后端实现，后端不感知前端渲染；数据库仅由业务服务层访问。

## 3. 请求流转流程

### 3.1 评论列表查询（读路径）
```
用户访问页面
  → 加载 /comment/* 静态资源（Nginx 返回，强缓存 7d）
  → 前端 GET /api/v1/comments?pageId=xxx&site=default
    → Nginx 限流检查 → 转发 Go 后端
      → Go 查内存缓存（key: site:page_id:page:pageSize，仅含已审核）
        → 命中 → 直接返回
        → 未命中 → 查 SQLite（is_audited=1 + 复合索引）→ 写缓存 → 返回
```

### 3.2 评论提交（写路径，v2 已移除乐观更新）
```
用户提交评论
  → 前端 POST /api/v1/comment
    → Nginx 全局限流（limit_req）
    → Go 参数校验（昵称/内容/邮箱/URL 格式）
    → 敏感词检查（命中 → is_audited=-1）+ 频率检查 + 重复内容检查
    → 写 SQLite（is_audited=0 待审，事务）
    → 立即返回「评论已提交，审核通过后显示」（不插入列表）
    → 异步协程：新评论待审通知管理员 / 缓存失效
```

### 3.3 管理员审核（审核路径）
```
管理员审核通过
  → PUT /api/v1/admin/comment/:id/audit {status:1}
    → JWT 鉴权中间件校验
    → UPDATE comments SET is_audited=1 WHERE id=?
    → 清除对应文章所有缓存分页
    → 公众可见
```

### 3.4 管理员登录
```
管理员操作
  → POST /api/v1/admin/register（首个用户，仅允许一次）
  → POST /api/v1/admin/login（失败不限定锁定，仅接口限流）
    → 校验账号密码（bcrypt）→ 签发 JWT（24h）
  → 携带 Authorization: Bearer <token> 调用管理接口
    → JWT 鉴权 + 登出黑名单校验
  → POST /api/v1/admin/logout → token 加入内存黑名单
```

## 4. 后端核心模块设计

### 4.1 路由模块
- 基于 `gin` 或 `http.ServeMux` 组织路由组
- **API 版本号前缀 `/api/v1/`**（决策 #16）
- 公共中间件：CORS（允许配置域名）、日志、Panic 恢复、请求限流
- 管理路由组加载 JWT 鉴权中间件 + 登出黑名单校验

### 4.2 缓存模块（LRU）
- 数据结构：`map[string]*list.Element` + `sync.RWMutex` 实现 LRU
- 缓存大小可配置（默认 512 条）
- 缓存 key：`site:page_id:page:pageSize`，存序列化分页数据（**仅含已审核评论**）
- 过期时间可配置（默认 60s）
- **失效策略**：评论审核通过 / 删除时主动删除该文章所有缓存分页

### 4.3 限流模块（双层）
| 层级 | 机制 | 策略 |
|------|------|------|
| 全局限流 | Nginx `limit_req` / `limit_conn` | 10r/s + burst |
| 接口级 | Go 滑动窗口 | 全局单 IP 每秒 ≤ 5 次（通用） |
| 内容级 | Go 计数器 + `rate_limits` 表 | 仅评论提交接口：单 IP 每秒 ≤ 5 次、每日 ≤ 20 条 |
| 登录级 | Go 计数器 | 单 IP 每分钟 ≤ 5 次；不做账号锁定 |

### 4.4 反垃圾与审核模块（v2 重写，全量审核）
审核策略统一为**全量人工审核**，不再区分「首次审核/智能审核」模式：

1. **全量待审**：所有评论提交后 `is_audited=0`，仅管理员审核通过后 `is_audited=1` 才对外展示
2. **本地敏感词库**：内嵌百级基础词库（可替换），命中自动标记 `is_audited=-1`（垃圾），**仍显示在待审列表中**供管理员查看
3. **评论频率检查**：单 IP 短时间连续相同内容拦截（返回 `2003`）
4. **链接限制**：可配置禁止链接 / 限制链接数量；默认不限制

> ⚠️ 已废除 v1 的「默认自动通过」「首次评论需审核」「仅含敏感词需审核」等多模式设计，统一为全量人工审核。此为产品决策，不可回退。

### 4.5 异步任务模块
- 协程 + 带缓冲 channel 任务队列（容量 100）
- 任务类型：
  - 邮件通知（管理员新评论待审通知、回复通知）
  - 清理过期缓存
  - 清理过期点赞记录（每日凌晨，`likes` 表 > 24h）
  - 清理过期限流记录（每日凌晨，`rate_limits` 表 > 30 天）
- **优雅退出**：监听 OS 信号，等待队列清空后关闭（**最长等待 30 秒超时后强制退出**，决策 #20）

### 4.6 邮件通知模块
- 基于标准库 `net/smtp`，支持 SSL/TLS
- 场景：
  - 新评论待审核通知管理员（开关 `notify_new_comment`，默认开启）
  - 评论被回复通知被回复者（开关 `notify_reply`，默认勾选）
  - 未配置 SMTP 时静默跳过
- 邮件模板内置，变量替换（站点名、评论内容、审核链接等）
- 异步发送，失败自动重试 2 次，记录日志

### 4.7 多站点支持
- 通过请求参数 `site` 区分站点（**不再使用 `X-Site-Id` HTTP 头**，决策 #11，防伪造）
- 默认 `site=default`，未传时自动归属 default
- 同一实例服务多个独立博客（表设计含 `site` 字段）
- 管理员可按站点筛选，可管理全部站点评论
- 服务端对 `site` 做归属校验

> ⚠️ 已移除 v1 中 Nginx `X-Site-Id` 头的设计，改为请求参数 `site` 传值，服务端做归属校验。

## 5. 安全设计

### 5.1 输入安全
- 全部参数化查询（SQLite prepared statement）
- 内容二次校验：长度、格式、特殊字符过滤
- 前端渲染转义，防 XSS
- 禁止评论内容嵌入 `<script>`、`<iframe>` 等标签

### 5.2 接口安全
- 评论提交：IP 频率限制 + 每日总量限制
- 管理接口：JWT 鉴权（存放在 `Authorization: Bearer <token>` Header，**不使用 Cookie，天然免疫 CSRF**）
- **登出接口**：将当前 token 加入内存黑名单（决策 #10）；重启后黑名单丢失，依赖 JWT 24h 自然过期
- **登录失败锁定**：不做账号锁定，仅依赖通用接口限流
- 管理接口 Referer/Origin 校验
- 错误信息不包含堆栈或数据库路径

### 5.3 内容安全
- 本地敏感词库：命中自动标记垃圾（`is_audited=-1`）
- **全量人工审核为最后防线**（决策 #1）
- 垃圾评论前台不展示，管理员可在后台查看

### 5.4 管理员账号安全
- 密码 bcrypt 哈希（cost ≥ 10）
- **首个通过 Web 注册的用户自动成为管理员**，注册成功后关闭后续注册，仅允许存在一个管理员
- 提供登录后修改密码接口；忘记密码需通过数据库或重新部署处理
- QQ 互联登录仅做辅助登录方式，首次登录需绑定已有的本地管理员账号
- 密码长度 ≥ 8 位，含数字和字母
- 不做登录失败锁定，仅依赖通用接口限流

## 6. 性能与资源预估

### 6.1 性能指标
| 指标 | 目标 |
|------|------|
| 缓存命中查询 | < 5ms |
| 数据库查询（≤1000 条评论） | < 15ms |
| 评论提交（含敏感词检测+写入，不含异步任务） | < 50ms |
| 并发 QPS | ≥ 500（1核2G 压测） |
| 5000 PV/日 | 资源几乎无波动 |

### 6.2 资源占用
| 组件 | 占用 |
|------|------|
| Go 后端 | 25~45MB |
| SQLite（内存映射） | 5~10MB |
| Nginx | 5~10MB |
| **整机** | **≤ 100MB**（最低支持 1核512MB） |

## 8. 关键技术决策记录（ADR）

| 编号 | 决策 | 理由 | 备选方案（已否决） |
|------|------|------|--------------------|
| ADR-01 | SQLite 用 `modernc.org/sqlite`（纯 Go） | 零 CGO 交叉编译 | `mattn/go-sqlite3`（需 CGO） |
| ADR-02 | 内存缓存用 map + RWMutex 自研 LRU | 无额外依赖 | Redis |
| ADR-03 | 前端原生 JS + 简单打包 | 零运行时依赖，构建仅做合并压缩 | Vue/React |
| ADR-04 | 异步任务用协程+channel | 队列容量 100 已覆盖 | MQ |
| ADR-05 | 后端两层返回：根评论分页 + 子评论全量 | 减少后端复杂度（决策 #12） | 后端扁平 / 后端树形递归 |
| ADR-06 | 多站点用请求参数 site | 防 X-Site-Id 伪造（决策 #11） | Nginx 头透传 |
| ADR-07 | 全量人工审核 | 产品决策，安全优先（决策 #1） | 自动通过 + 可选审核 |

## 9. 需求澄清后的技术落地要点（v2.1 新增）

### 9.1 评论列表返回结构
- 后端返回**两层结构**：
  - `roots`：根评论数组（含置顶），按置顶优先 → 时间正序。
  - `children`：子评论数组，按时间正序；由前端根据 `parent_id` 挂载到对应根评论下。
- 分页仅针对根评论；子评论一次性全量返回。
- 默认每页 10 条，公开接口最大 50 条、管理接口最大 100 条，页码从 1 开始。

### 9.2 图片与评论渲染
- 支持 **Markdown 图片语法** `![](url)`；其余 Markdown 不支持。
- 前端自动识别文本中的图片 URL（`jpg/jpeg/png/gif/webp`）并渲染为 `<img>`。
- 不实现后端图片上传，用户直接粘贴图片 URL。

### 9.3 头像生成
- 后端统一返回 `avatar_url`，前端不接触邮箱字段。
- 有邮箱：后端返回 Gravatar URL。
- 无邮箱：后端不返回 `avatar_url`，前端基于昵称哈希生成几何图形 SVG（随机颜色 + 图形）。

### 9.4 管理员账号
- 提供 `/api/v1/admin/register` 接口，**仅首个请求成功**，后续返回 403。
- 首个注册用户角色为管理员。
- 提供 `/api/v1/admin/password` 修改密码接口（需登录）。
- 不做登录失败锁定，仅接口限流。

### 9.5 配置存储
- `settings` 表为 key-value 结构，支持按 `site` 隔离。
- 启动时读取必要配置（如 SMTP）到内存；运行时修改后即时生效或下次请求生效。

### 9.6 限流
- 评论提交接口单 IP 每秒 ≤ 5 次、每日 ≤ 20 条。
- 重复内容：5 分钟内、同一 `pageId`、同一 IP 相同内容拦截。
- 通用接口限流：Nginx 10r/s + burst，Go 层单 IP 每秒 ≤ 5 次滑动窗口。

### 9.7 多站点
- 请求参数 `site`；未传时默认 `default`。
- 缓存 key 包含 `site`，避免跨站点污染。
- 管理员后台可按站点筛选全部站点数据。
