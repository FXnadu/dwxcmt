# 07 - 性能测试报告

> 测试时间：2026-08-13（Asia/Shanghai，一次完整可复现编排，数据来自 `scripts/bench-all.ps1` 自动采集，非估算）
> 被测系统：dwxComment（Go 1.26 + SQLite + modernc.org/sqlite，单二进制）
> 文档站点（含图表展示）：<https://deepwhitex.com/dwxcmt/>

---

## 1. 测试环境与口径

- **本地**：Windows，Go 1.26，单文件二进制 21.5MB。
- **两套配置**：
  - `config/config-stress.yaml`（严格）：限流 50 req/s/IP、1000 条/日/IP，SQLite 独立库，用于验证限流规则。
  - `config/config-bench.yaml`（基准）：与严格配置仅限流不同（100 万/秒、100 万条/日，等效不限流），用于测量真实容量。
- **工具**：hey（读压测）、`scripts/stress-write.py`（写压测，keep-alive 持久连接）、pprof（127.0.0.1:6060 内存采样）。
- **口径**：限流拒绝（业务码 2001/2002）是设计内行为，HTTP 状态仍为 200，与 HTTP 错误（连接失败/5xx/超时）分别统计。早期报告「7.9 万 req/s」实为**限流响应被计入吞吐**的口径错误，已弃用，以本次实测为准。

## 2. 本地压测结果

### 2.1 读路径 · 真实容量

5 实例 × 20 并发 × 30s，空库列表查询，限流放宽（等效不限流），累计 **1,334,644** 次响应，**0 错误**：

| 指标 | 数值 |
|---|---|
| 单实例 QPS | 8.7k ~ 9.2k req/s |
| **合计 QPS** | **≈ 44,481 req/s** |
| 平均延迟 | 2.2 ~ 2.3 ms |
| p99 | ≤ 11.8 ms |
| 独立逐请求采样（n=605,354） | p50 0.4ms / p99 2.2ms / p99.9 8.2ms，非 200 为 0 |

### 2.2 写路径 · 单 IP 最坏场景（限流验证）

严格实例，32 并发伪造同一 IP 攻击 ≈ 800 req/s，总请求 19,447（25s）：

| 业务码 | 数量 | 说明 |
|---|---|---|
| code=0（成功入库） | **1,000** | **精确触顶每日上限 1000 条** |
| code=2001（每秒限流） | 18,197 | 50 req/s 精确生效 |
| code=2002（日配额） | 250 | 通过每秒限流但超出日配额 |
| 业务错误 / HTTP 错误 | **0 / 0** | — |

理论校验：每秒放行 50 × 25s = 1,250 = 1,000（成功）+ 250（日配额拒绝）✓

### 2.3 写路径 · 真实吞吐

bench 实例，32 并发不限速，10s：**10,144 条入库，≈ 1,008 条/s**，平均延迟 31.6ms，业务/HTTP 错误 0/0。

### 2.4 内存与 goroutine（pprof 采样）

| 采样对象 | WorkingSet 峰值 | HeapInuse 峰值 | goroutine 峰值 |
|---|---|---|---|
| 写压测期间 | 26.4 MB | 4.6 MB | 43 |
| 读压测期间 | 29.2 MB | 7.7 MB | 147 |

压测结束后 goroutine 回落至 31，无泄漏。**单实例整机 WorkingSet ≤ 29.2 MB，1 核 512MB 机器实测占用约 5%。**

## 3. 线上部署验证（cmt.example.com）

- **可达性**：健康检查 HTTP 200；TTFB 稳定后中位数 ≈ 58ms（网络 RTT 约 22ms，服务端处理为毫秒级）。
- **限流**：同一 IP 12 连发 → 6 成功 + 6 被限流（业务码 2001），5 req/s/IP 精确生效。
- **IP 伪造防护**：伪造 `X-Forwarded-For` 无效，服务端从右向左取第一个非可信 IP。
- **CORS / TLS / 静态缓存**：白名单 Origin 正确返回 CORS 头、预检 204；TLS 证书校验通过；静态资源 7 天强缓存 + ETag。
- **小并发压测**：40 请求 × 5 并发，平均 14.3ms，全部 HTTP 200，无 5xx。

## 4. 结论

1. 读路径真实容量 ≈ **44,481 req/s**（5 实例并行、限流放宽口径），p99 ≤ 11.8ms，133 万次响应 0 错误。
2. 写路径单 IP 最坏场景（800 req/s 攻击）下，每秒限流与每日上限**精确生效**，0 业务错误、0 HTTP 错误；真实写吞吐 ≈ 1,008 条/s。
3. 单实例 WorkingSet 峰值 29.2MB、HeapInuse 7.7MB，goroutine 无泄漏，**1 核 512MB 机器可运行**。
4. 线上限流、CORS、TLS、静态缓存、IP 伪造防护全部按设计生效。

## 5. 数据可信度

- 所有数字来自 `scripts/bench-all.ps1` 一键编排的自动采集（hey / stress-write.py / pprof），非估算；服务端日志全程留底（0 字节，无 panic）。
- 严格配置与放宽配置分开测量：限流验证看严格配置，容量测量看放宽配置，避免"被规则拦下的请求"误算成成功。
- 样本量大（读路径 133 万次、延迟单独采样 60.5 万次、写压测逐秒记录 25s），且排除了三类压测客户端自身干扰（临时端口耗尽假错误、curl 客户端瓶颈、强制 GC 假内存）。
- 本报告为**本机空库、限流放宽**口径，生产折算建议按 1/5 ~ 1/10 打折看待，不代表生产承诺。

## 6. 复现方式

1. `go build -o dwx-stress main.go`，以 `config/config-stress.yaml` 启动。
2. 执行 `scripts/bench-all.ps1`（自动切换 bench 实例并产出全部原始数据）。
3. `python scripts/gen-perf-charts.py <产物目录> --charts-dir <输出>` 渲染图表。
4. 线上长稳观测：`bash scripts/monitor.sh $(pgrep -f dwx-comment) <输出.csv>` 按小时采样后汇总。
