## 1. 编译与交付

### 1.1 一键打包（推荐，版本号自动 +1）
Windows 下执行根目录的 `build.ps1`，每次打包自动递增版本号并注入：

```powershell
.\build.ps1                            # 本机平台编译，版本 patch +1（如 v1.0.0 -> v1.0.1）
.\build.ps1 -OS linux -Arch amd64      # 交叉编译 Linux amd64
.\build.ps1 -OS linux -Arch arm64 -Front   # 先 npm 构建前端再交叉编译
.\build.ps1 -Tag                       # 编译成功后自动打 git tag
.\build.ps1 -SkipBump                  # 不递增，用当前 VERSION 重新编译
```

版本规则：
- 当前版本保存在仓库根目录 `VERSION` 文件（形如 `v1.0.0`），随代码提交可追溯；
- 每次打包将 patch 位 +1，并通过 `-ldflags "-X dwxcmt/controller.Version=..."` 注入；
- 编译成功后才写回 `VERSION`，编译失败不产生版本变更；
- 版本号可通过健康检查 `/api/v1/health` 验证。

### 1.2 手动交叉编译（零 CGO）
```bash
# 版本号通过 -ldflags 注入（不注入则默认为 dev）
# Linux amd64
GOOS=linux GOARCH=amd64 go build -ldflags="-s -w -X dwxcmt/controller.Version=v1.0.0" -o dwx-comment main.go

# Linux arm64
GOOS=linux GOARCH=arm64 go build -ldflags="-s -w -X dwxcmt/controller.Version=v1.0.0" -o dwx-comment main.go
```
> 依赖 `modernc.org/sqlite`（纯 Go），无需 CGO 交叉编译工具链。
> `-X dwxcmt/controller.Version=...` 将版本号注入健康检查 `/api/v1/health` 的返回，建议与 git tag 保持一致。

### 1.3 交付物清单
| 文件 | 说明 |
|------|------|
| `dwx-comment` | 编译后的二进制 |
| `config.yaml` | 配置文件（含 QQ OAuth、SMTP 等配置项） |
| `front/` | 前端静态资源目录（含 `comment.html`、`comment.js`、`admin.html`） |
| `migration/` | 数据库迁移脚本目录 |

## 2. 服务器部署

### 2.1 目录规划
```bash
/opt/dwx-comment/
├── dwx-comment        # 二进制
├── config.yaml          # 配置
├── front/               # 前端资源（含 comment.html / admin.html）
├── migration/           # 迁移脚本
└── comment.db           # 首次运行自动生成
```

### 2.2 首次部署步骤
```bash
# 1. 创建目录与用户
mkdir -p /opt/dwx-comment/{front,scripts,migration}
useradd -r -s /usr/sbin/nologin www-data

# 2. 上传二进制、前端、配置、迁移脚本
scp -r dwx-comment config.yaml front migration www-data@server:/opt/dwx-comment/

# 3. 赋权
chown -R www-data:www-data /opt/dwx-comment
chmod +x /opt/dwx-comment/dwx-comment

# 4. 创建初始管理员（Web 注册）
#    启动服务后访问 https://yourdomain.com/admin/ 注册
#    首个注册账号自动成为站长（is_owner=1）；后续注册默认待审批（is_approved=0），
#    需站长登录后台「账号管理」审核通过后方可登录，注册接口不再关闭

# 5. 启动（systemd 托管，见第 3 节）
```

### 2.3 配置文件 `config.yaml`（v3.1 完整）

```yaml
server:
  port: 8080
  mode: release            # debug / release

database:
  path: ./comment.db

auth:
  jwt_secret: "your-32-char-secret"   # 生产必须修改！
  jwt_ttl: 86400                      # 24 hours in seconds

qq_oauth:                   # [v2 新增] QQ 互联（可选，留空则关闭该登录方式）
  app_id: ""
  app_key: ""
  redirect_uri: "https://api.example.com/api/v1/admin/qq/callback"

github_oauth:               # [v3.1 新增] GitHub OAuth（可选，留空则关闭该登录方式）
  client_id: ""
  client_secret: ""
  redirect_uri: "https://api.example.com/api/v1/admin/github/callback"

smtp:
  host: "smtp.example.com"
  port: 587
  username: "noreply@example.com"
  password: ""
  use_ssl: false

rate_limit:
  requests_per_second: 5
  comments_per_day: 20

comment:
  content_max_length: 500
  nick_max_length: 20
  max_pinned_per_page: 3         # [v2 新增]
  max_reply_depth: 3

cors:
  allowed_origins:
    - "https://blog.example.com"

trusted_proxy:              # [v3.1 新增] 可信反代 IP/CIDR，命中才读取转发头
  proxies:
    - "127.0.0.1/32"        # Nginx 同机部署信任回环即可
    - "::1/128"
```

> **安全提示**（v3.1）：
> - `trusted_proxy.proxies` 为空时**完全不信任** `X-Forwarded-For`/`X-Real-IP`，直连 `RemoteAddr`（最安全，但会丢失真实 IP，影响限流与防刷）；生产前置 Nginx/CDN 时必须追加其出口 IP/CIDR。
> - SMTP 用于邮箱验证码（注册/登录 2FA）与评论回复通知，必须正确配置。
> - QQ / GitHub OAuth 为可选的辅助登录方式，留空则关闭。

## 3. systemd 进程托管

```ini
# /etc/systemd/system/dwx-comment.service
[Unit]
Description=dwxComment Service
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/dwx-comment
# -config 指向二进制同级的 config.yaml（程序默认相对路径为 config/config.yaml，此处显式指定）
ExecStart=/opt/dwx-comment/dwx-comment -config config.yaml
Restart=always
RestartSec=5
User=www-data
LimitNOFILE=65536
# 优雅退出超时 30 秒（决策 #20）
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now dwx-comment
systemctl status dwx-comment
journalctl -u dwx-comment -f        # 实时日志
```

> 优雅退出：程序监听 OS 信号，等待异步任务队列清空后关闭，最长 30 秒后强制退出。

## 4. Nginx 配置

### 4.1 全局限流区（http 块）
```nginx
limit_req_zone $binary_remote_addr zone=comment:10m rate=10r/s;
```

### 4.2 站点配置
```nginx
server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    # 安全响应头
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;

    # 前端静态资源（强缓存）
    location /comment/ {
        alias /opt/dwx-comment/front/;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # 管理页（admin.html 位于 front/ 目录，与评论组件同目录）
    location /admin/ {
        alias /opt/dwx-comment/front/;
    }

    # API 转发（限流）
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        limit_req zone=comment burst=10 nodelay;
    }
}
```

> ⚠️ [v2 变更] 已移除 v1 中 `X-Site-Id` 头透传（安全原因，决策 #11），站点标识统一用请求参数 `site`。

```bash
nginx -t && systemctl reload nginx
```

## 5. 备份与恢复

### 5.1 备份方式

当前版本未提供 `scripts/backup.sh`，推荐以下任一方式备份：

**通过管理接口备份（推荐）**：
- `GET /api/v1/admin/backup`：一键备份（FR-36），服务端执行 WAL checkpoint 后将数据库整体拷贝到数据库同级 `backups/` 目录（如 `backups/comment_20260810_030000.db`），仅保留最近 7 份，超出自动删除最旧；
- `GET /api/v1/admin/export`：全量导出 JSON（见《04-API接口文档》§4.1/§4.3）。

**手动备份（需 sqlite3 CLI）**：
```bash
DB="/opt/dwx-comment/comment.db"
BACKUP_DIR="/backup/comment"
mkdir -p "$BACKUP_DIR"
sqlite3 "$DB" "PRAGMA wal_checkpoint(TRUNCATE);"
cp "$DB" "$BACKUP_DIR/comment_$(date +%Y%m%d%H%M).db"
```
> WAL 模式下务必先停服再替换文件，避免 -wal / -shm 残留文件不一致。
> 手动备份依赖 `sqlite3` CLI（系统级工具，不影响程序零 CGO 属性）；推荐优先使用管理接口一键备份（无需 sqlite3 CLI）。

### 5.2 定时备份（crontab）
```cron
# 每天凌晨 3 点执行手动备份命令
0 3 * * * sqlite3 /opt/dwx-comment/comment.db "PRAGMA wal_checkpoint(TRUNCATE);" && cp /opt/dwx-comment/comment.db /backup/comment/comment_$(date +\%Y\%m\%d\%H\%M).db >> /var/log/lc-backup.log 2>&1
```

### 5.3 恢复流程
```bash
systemctl stop dwx-comment
cp /backup/comment/comment_202608050300.db /opt/dwx-comment/comment.db
chown www-data:www-data /opt/dwx-comment/comment.db
systemctl start dwx-comment
```
> WAL 模式下务必先停服再替换文件，避免 -wal / -shm 残留文件不一致。
> 恢复流程适用于所有备份来源（管理接口 `backups/` 快照或手动拷贝均可，替换为对应备份文件路径）。

## 6. 升级策略

### 6.1 常规升级
```bash
# 1. 备份数据库（按 5.1 节方式）
sqlite3 /opt/dwx-comment/comment.db "PRAGMA wal_checkpoint(TRUNCATE);" && cp /opt/dwx-comment/comment.db /backup/comment/comment_$(date +%Y%m%d%H%M).db

# 2. 替换二进制 + 迁移脚本（保留 config.yaml 与 comment.db）
cp dwx-comment.new /opt/dwx-comment/dwx-comment
cp -r migration.new/* /opt/dwx-comment/migration/
chmod +x /opt/dwx-comment/dwx-comment

# 3. 重启（程序自动执行数据库迁移）
systemctl restart dwx-comment

# 4. 验证
journalctl -u dwx-comment -n 50
curl -s http://127.0.0.1:8080/api/v1/health
```

### 6.2 数据库自动迁移
- 程序启动时比对 `migration_versions` 表最大版本与 `migration/` 脚本
- 逐级执行未应用的迁移 SQL（事务包裹，失败回滚）
- 升级前建议先备份，迁移失败时可通过恢复旧库回滚

## 7. 管理员账号管理

### 7.1 多管理员模型（v3.1）
- **首个注册账号自动成为站长**（`is_owner=1`），注册接口不再关闭；
- **后续注册账号默认待审批**（`is_approved=0`），需站长登录后台「账号管理」审核通过后方可登录；
- 站长可**审核 / 禁用**其他管理员（禁用的账号无法登录，错误码 7011）；
- 站长拥有全部权限；非站长管理员由 `can_delete` 决定是否有删除/批量删除权限（v3.1，默认无删除权限）。

### 7.2 登录与安全（v3.1）
- **邮箱密码登录**：`POST /api/v1/admin/login`；
- **邮箱验证码登录**：`POST /api/v1/admin/email/login`（未配置 SMTP 时不可用）；
- **2FA 两步验证**（可选，邮箱验证码）：登录密码验证通过后返回预授权凭证，再调用 `POST /api/v1/admin/login/2fa` 提交邮箱验证码完成登录；管理员可在个人中心开启/关闭（`POST /api/v1/admin/2fa/enable` / `disable`）；
- 支持 **QQ / GitHub OAuth** 辅助登录（首次需绑定已有本地管理员账号）。

### 7.3 常用操作
| 操作 | 方式 |
|------|------|
| 创建初始管理员 | 启动服务后访问 `/admin/` 页面 Web 注册（首个自动成为站长） |
| 注册新管理员 | 注册后待站长审批；或站长在「账号管理」中审批通过 |
| 审核/禁用管理员 | 站长在后台「账号管理」操作（接口：`POST /api/v1/admin/accounts/{id}/approve`、`PUT .../disabled` 等，见《04-API接口文档》§3.13） |
| 修改密码 | 登录后通过 `PUT /api/v1/admin/password` 接口修改 |
| 忘记密码 | 需站长在后台重设，或直接操作数据库处理 |

> 密码要求：≥ 8 位，含数字和字母。bcrypt 哈希存储（cost ≥ 10）。
> OAuth 登录为辅助方式，首次登录需绑定已有本地管理员账号。
> 不做登录失败锁定，仅依赖 IP 限流（单 IP 每分钟 ≤ 5 次）。

## 9. 安全加固清单

- [ ] 修改 `config.yaml` 中 `jwt_secret` 与管理员密码（必须）
- [ ] 服务器仅开放 80/443，8080 端口不对外（防火墙/安全组）
- [ ] 启用 HTTPS（Let's Encrypt 免费证书）
- [ ] 管理员密码使用强密码（≥12 位混合）
- [ ] 生产环境 `server.mode: release`
- [ ] 配置 CORS 白名单，仅放行自己站点域名
- [ ] 定期执行 `PRAGMA integrity_check` 检查库完整性
- [ ] 备份文件存放于独立磁盘或异地存储
- [ ] QQ 互联 `app_key` 等敏感配置不提交版本控制

## 10. 故障排查

| 症状 | 可能原因 | 排查命令 |
|------|----------|----------|
| 评论提交 502 | Nginx 转发目标不可达 | `curl http://127.0.0.1:8080/api/v1/health` |
| 评论全被限流 429 | 限流配置过严 | 检查 Nginx `limit_req` 与 Go `rate_limit` |
| 图片/表情不显示 | 静态资源路径错误 | `curl -I https://domain/comment/comment.js` |
| 邮件通知失败 | SMTP 配置错误 | `journalctl -u dwx-comment` |
| QQ 绑定回调失败 | redirect_uri 不匹配 | 核对 QQ 互联后台与 config.yaml |
| 数据库锁定错误 | 多进程同时访问 | 确认仅一个服务实例在运行 |
| 升级后启动失败 | 迁移脚本执行失败 | 查看日志 + 恢复备份回滚 |
